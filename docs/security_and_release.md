# Security and release governance

Current prototype is a CLI and GitHub files, not a multi-user production service. No login/authentication, real identity provider, signature authority, database migration or regulatory privacy guarantee is provided. A hash chain detects content changes only if compared to a trusted independently held prior digest; it is not actor authentication.

Avoid uploading nonpublic original AR6 scenario rows, local RP24 identity/value reviewer packets, contact information, model embargoes, solver license keys or copyrighted assessment figures. Project A's source licenses and data permissions remain separate from this project's MIT code license.

Current release modes: SIMULATION_ONLY for author-authored fixtures, SOURCE_BACKED_COVERAGE_ONLY for hash-verified allowed empirical aggregates, and EXTERNALLY_EXERCISED only after separately attributable consenting external actions and real issue/review exchange. Project B never decides that I3 is scientifically true from a manifest label. Real deployment must add actual authentication, access control, user consent, retention schedules, audit log anchoring and independently reviewed source licensing.

Synthetic timeline dates, meeting notes and fictitious submitters must always be explicitly marked simulated. No claims of completed IIASA coordination, official IIASA alignment or production use.
